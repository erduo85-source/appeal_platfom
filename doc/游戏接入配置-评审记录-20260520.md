# 游戏接入配置评审记录

## 评审背景

内部需求评审后，对「游戏接入配置」相关需求进行补充修订。本次记录用于同步评审结论、明确后续需求调整点，并标记仍需确认的问题。

## 评审结论

本期能力仍围绕 SDK 内部使用场景展开，暂不扩大到更多业务角色。后续重点调整项目数据来源、按钮权限、提示文案、表单说明和多 appid 接入能力；抽屉列表顶部切换维度需进一步确认。

## 需求调整点

| 序号 | 调整项 | 评审意见 | 处理方向 |
| ---: | --- | --- | --- |
| 1 | 接入项目数据源 | 接入项目下拉列表的数据来源改为平台服务中心的项目列表。 | 后续需求与原型中统一替换数据来源说明。 |
| 2 | 配置入口权限 | 页面「游戏接入配置」按钮需配置可见权限和编辑权限，本期只开放给 SDK 内部。 | 明确按钮可见、进入抽屉、编辑保存等权限边界。 |
| 3 | 抽屉提示文案 | 抽屉顶部提示文案需要精简。 | 保留同步时效和影响范围，减少冗长说明。 |
| 4 | 游戏名称说明 | 接入配置中的「游戏名称」需写明是用户端对外展示、玩家申诉时看到的游戏名称。 | 在表单 label、说明文案或 placeholder 中补充展示含义。 |
| 5 | 列表顶部切换 | 抽屉内申诉列表顶部需要评估做「发行主体切换」还是「账号体系切换」。 | 暂不定论，需产品和业务确认最终切换维度。 |
| 6 | 接入项目多选 | 接入项目下拉列表需要支持多选，用于适配多端项目有多个 appid 的情况。 | 补充多选交互、保存结构和展示规则。 |

## 待确认问题

| 问题 | 说明 | 建议确认方 |
| --- | --- | --- |
| 切换维度 | 抽屉内申诉列表顶部应按发行主体切换，还是按账号体系切换。该选择会影响列表筛选、保存范围和权限边界。 | 产品、业务、SDK |
| 多 appid 保存规则 | 同一个游戏选择多个 appid 后，是否共用同一个展示游戏名称、LOGO、排序和状态。 | 产品、SDK |
| 多选后的展示规则 | 下拉框、列表 appid 列、编辑弹窗中如何展示多个 appid，是否需要折叠或 tooltip。 | 产品、设计 |

## 后续处理建议

| 优先级 | 建议事项 | 说明 |
| --- | --- | --- |
| P0 | 先确认切换维度 | 「发行主体」和「账号体系」会影响数据组织方式，应先锁定。 |
| P0 | 明确多选保存规则 | 多 appid 支持会影响表单、列表展示和提交结构，需要先确定规则。 |
| P1 | 更新需求文档 | 将平台服务中心数据源、SDK 内部权限、游戏名称说明同步进需求文档。 |
| P1 | 更新原型文案 | 精简抽屉提示，并补充游戏名称字段说明。 |

## 对话框精简描述

已整理评审意见：本次主要调整项目数据源、SDK 内部权限、抽屉提示文案、游戏名称说明、多 appid 多选支持，并保留「发行主体 / 账号体系切换」作为待确认项。建议下一步优先确认切换维度和多选保存规则，再更新需求文档与原型。
